Generate Go functions bindings for the Turso - SQLite-compatible embedded database written in Rust.
You must use C API bridge implemented in Rust which expose ABI compatible functions to interact with the database.

Inspect purego documentation, Rust bindings, current functions for loading of the library.

## IMPORTANT

Naming:
* The package name is "turso_go"
* Use `sqlite3_.*` or `libsql_.*` naming convention for function names
  - For C functions, prepend `c_` prefix to the variable name
* Use exactly same names for functions as in Rust bindings (with `c_` prefix for purego functions). Do not add anything extra
* Emit **all** methods (do not foget about `sqlite_value_*` methods - they will be useful in other extensions of Go SDK)

Structure:
* Introduce necessary constants which are used in the public API of the bindings (return codes, parameters, default strings, etc)
  * All constants must ready to use in the wrappers (e.g. must have proper type, expected by the input param or corresponding output parameter)
  * Note, that Go require constant to be converted explicitly to custom type wrappers (e.g. `const TursoStepRow TursoStep = TursoStep(SQLITE_ROW)`)
* Define necessary constants (error codes, strings) at the top of the bindings file
* Define main structs at the top of the bindings file
* Wrap bindings in go functions which make them more ergonomic:
  * Return error as last output parameter instead of int32 error code
  * Return value (if any) instead of out parameter
* Do not expose any additional methods / split Rust methods in parts - just translate methods in 1:1 relation to Go
* All library methods **must** be registered on it as this is slow operation and we must not do that after startup
* Do not check db/stmt pointers for nilness - rely on the developer to pass proper pointers
  * This will allow some methods to return result without error (as original bindings)
* Use following simple snippet as reference (other methods are more complex):
```go
func sqlite3_initialize() error {
	rc := c_sqlite3_initialize()
	if rc != SQLITE_OK {
		return &TursoError{Code: rc, Message: c_sqlite3_errstr(rc)}
	}
	return nil
}
```

Errors:
* Introduce special error type `type TursoError struct { .. }` which will hold return code, message and optional inner error (which will be used for errors.Is implementation)
* Always set optional out parameter for error if Rust method has it
* Always prefer message generated by the method as extra out parameter if Rust has it. 
  * Otherwise, try to get last error through sqlite3_errmsg / sqlite3_errstr methods
* Return `error` interface which will hold either `nil` or `&TursoError` as error result where function can fail
* Add `ErrTursoConstraint` and maybe other sentinel errors in order for user to check for specific failure conditions
* Implement Unwrap which return inner Err of `TursoError` struct
* Properly embed sentinel errors in case of certain return error codes
* Example of helper to use for error conversion:
```go
func tursoError(db TursoDb, code int32, msg string) *TursoError {
	if msg == "" && db.ptr != nil {
		msg = c_sqlite3_errmsg(db.ptr)
	}
	if msg == "" {
		msg = c_sqlite3_errstr(code)
	}
	err := &TursoError{Code: code, Message: msg}
  // you can handle more cases here
  if code == SQLITE_CONSTRAINT {
    err.Inner = ErrTursoConstraint
  }
	return err
}
```

Recommendations:
* Load the library with the `loadLibrary` function (already implemented - you can freely use it)
  * Use `turso_sqlite3` as load library name
  * Panic immediately if you can't load the library or functions due to whatever reason
  * Initialization must either succeed or panic
* Use `RegisterLibFunc` to register foreign function (note, that it returns no error!)
  * Use following snipppet as reference:
  * `purego.RegisterLibFunc(&c_sqlite3_shutdown, tursoLibrary, "sqlite3_shutdown")`
* Add explicit `registerBindings` function which must ensure that all necessary functions are registered in Go
* Follow same order of definition as sqlite3 bindings in Rust
* Introduce few type aliases for extra type safety (convert them manually to pointers in the method implementations if needed):
  * `TursoDb` - transparent wrapper on top of db pointer (methods **must** explicitly accept `TursoDb`)
  * `TursoStatement` - composite type which holds statement and db pointers (db pointer can be used to extract proper error)
  * `TursoStep` - enumeration for step result
  * `TursoValue` - holds pointer to the value which can be operated with `sqlite3_value_*` functions 
  * Never return or accept row `unsafe.Pointer` in the go wrappers - always either use some custom or native type (e.g. []byte, string, etc)
* Do not handle any callbacks/destructors (even if Rust has them). Always pass nil in such parameters and do not accept any callbacks in the wrapper signatures
* Be careful with `sqlite3_free` usage as it free pointer with libc function (so if it were some internal Rust object - this will be wrong). 
  * In case when you can't properly free resources with current FFI layer - you **must** leave TODO comment (e.g. // todo(agent): ...)
* Add links to the external resources if applicable or cite purego/tursodb docs in non-trivial places
* Return `TursoStep` result from `sqlite3_step() (TursoStep, error)` for successful executions of the step (Row / Done)
* If wrapper require non-trivial logic (due to allocations, memory safety, etc) - write down note first in the body of the function (e.g. // note(agent): ...)

Code style:
* Do not add unnecessary docstrings which just duplicate obvious things (like function name, enumerate args, etc)
* Do not add unnecessary helper methods / lambdas if their code can be easily inlined without any downsides
* Do not write unused code (functions, helper). Only emit code which will be directly used in the Go wrappers
* Avoid unnecessary allocations
* Avoid usage of global variables if possible
* Always check error first and later return value + nil if there were no error

Dependencies:
* Use "github.com/ebitengine/purego" - do not use CGo
* Do not use any other external dependencies - only purego and Go native stdlib

Purego gotchas:
* Remember, that purego already do marshaling of string parameters (by converting them to zero-terminated string and keep alive parameters)
* Inspect docstrings for purego functions to get more details
* Do not use any types in bindings which are not explicitly mentioned in the RegisterFunc signature

Bindings gotchas:
* Return (string, error) from `sqlite3_column_text` as due to GIGO rule SQLite can have non-utf8 string in the columns
